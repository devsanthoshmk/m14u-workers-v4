# Open music catalog APIs for M14U

Checked 2026-11-25. The goal is keyless catalog search, artwork, and full audio, using the [existing split](ARCHITECTURE.md) between Worker metadata and direct client playback. An open API, an openly licensed recording, and a playable URL are three separate things. None of the sources below was shown to replace a mainstream, on-demand music catalog.

## Internet Archive: recommended for a curated first provider

- **Find releases or shows:** call `https://archive.org/advancedsearch.php` with `q=collection:netlabels AND mediatype:audio AND title:"ambient"`, repeat `fl[]` for `identifier`, `title`, `creator`, and `licenseurl`, and set `rows`, `page`, and `output=json`. Read `response.docs`. That is item-level search: individual songs within a release or concert are not guaranteed to appear by title. Begin with a collection constraint instead of all `mediatype:audio`; audio can include speech and books. Sources: [Advanced Search](https://archive.org/advancedsearch.php), [Netlabels](https://archive.org/details/netlabels), [metadata schema](https://archive.org/developers/metadata-schema/index.html).
- **Resolve tracks:** `GET https://archive.org/metadata/{identifier}` returns item `metadata` and a `files` array. Select compatible public audio (e.g. `VBR MP3` or `MP3` first) and use file-level `title`, `creator`, `track`, and `length` where present. Treat empty `{}` or missing `files` as unavailable; do not assume these fields or an MP3 always exist. An item can contain originals and derivatives of the same recording; prefer one playable rendition per track and use the `original` link where present to help deduplicate. Source: [Item Metadata API: Read](https://archive.org/developers/md-read.html), [live sample](https://archive.org/metadata/frec011).
- **Artwork and audio:** use `https://archive.org/services/img/{identifier}` as an item thumbnail, not a guaranteed album cover. A missing item can return `200` with a redirect to the Archive placeholder. Audio uses `https://archive.org/download/{identifier}/{filename}` (encode the identifier and each path segment); let playback follow the redirect and store the stable URL, not the storage hostname. Sources: [Internet Archive items](https://archive.org/developers/items.html), [thumbnail sample](https://archive.org/services/img/frec011), [MP3 sample](https://archive.org/download/frec011/fst_ambientimprovisations_vol2_01.mp3).
- **Rights and access:** keep the original item URL, creator, and license URL. Use a reviewed collection and a license allowlist appropriate to the planned use, with required attribution. Verify rights separately for the image. Skip restricted items, private files, and missing or ambiguous licenses in the initial provider. A catalog document, a listed MP3, or even a successful Range response does not override an access designation or grant reuse rights. Sources: [Archive rights guidance](https://help.archive.org/help/rights/), [terms](https://archive.org/about/terms), [automated access guidance](https://archive.org/developers/bots.html), [stream-only example metadata](https://archive.org/metadata/gd77-05-08.sbd.hicks.4982.sbeok.shnf).

**Live:** the Netlabels ambient search returned 185 items. [`frec011`](https://archive.org/details/frec011) listed a CC BY-NC-ND 2.0 license: useful as a technical sample, not a default allowlist entry. Its thumbnail returned JPEG, and its first MP3 followed a redirect to an Archive storage host and returned `206 audio/mpeg`, `Content-Range: bytes 0-1023/19089408`, and `Access-Control-Allow-Origin: *`. The Grateful Dead soundboard sample listed `access-restricted-item: true` and belonged to `stream_only` even though its MP3 answered a Range request. Collection-only `collection:GratefulDead` worked, but an attempted combined `collection:etree AND mediatype:audio AND creator:"Grateful Dead"` returned zero; test query shapes rather than treating empty results as a coverage verdict.

## Alternatives

### Openverse: keyless cross-source discovery, variable media delivery

[`GET /v1/audio/?q=jazz&page_size=2`](https://api.openverse.org/v1/audio/?q=jazz&page_size=2) returned JSON when sent `Accept: application/json`. Results include media `url`, `thumbnail`, source/landing page and license data. Openverse is an index: clients ultimately depend on the source host for the audio. The [authentication and throttling docs](https://docs.openverse.org/api/reference/authentication_and_throttling.html) describe anonymous limits and optional registration; the [terms](https://docs.openverse.org/terms_of_service.html) do not remove the need to verify the source and license. Test by source and use placeholder artwork. In the sample, a Jamendo-hosted “Jingle Jazz” asset returned `206 audio/mpeg` with a 12,224,068-byte total, no CORS header, and a returned Openverse thumbnail URL gave `403`. This confirms bytes were available for that source, not guaranteed full playback for every result.

### Wikimedia Commons: keyless open audio, no dependable album covers

Use the MediaWiki Action API search generator in file namespace `6`, e.g. `gsrsearch=filetype:audio Beethoven`, with `prop=imageinfo&iiprop=url|mime|extmetadata` for the direct URL, type, and license/credit fields. The file page is the review and attribution link; don't assume a sound recording has album art. Sources: [search API](https://www.mediawiki.org/wiki/API:Search), [imageinfo API](https://www.mediawiki.org/wiki/API:Imageinfo), [Commons reuse guidance](https://commons.wikimedia.org/wiki/Commons:Reusing_content_outside_Wikimedia), [User-Agent policy](https://foundation.wikimedia.org/wiki/Policy:Wikimedia_Foundation_User-Agent_Policy). The Beethoven search gave an [Ogg recording marked CC BY-SA 2.0](https://commons.wikimedia.org/wiki/File:Beethoven_Prometheus_Creatures_Op._43_No._14_-_Solo_della_signora_Cassentini.oga); its original answered `206` with `Access-Control-Allow-Origin: *`. Test actual Ogg playback on each target before adding it to a cross-platform catalog.

### Audius: promising independent streaming, not a default open-license source

The [Audius REST API reference](https://docs.audius.co/api/) advertises search and streaming. [Track search](https://api.audius.co/v1/tracks/search?query=lofi) worked without credentials and returned duration, `artwork` sizes, `is_streamable`, access and license fields. Three streamable hits, including [`ng9rl`](https://api.audius.co/v1/tracks/ng9rl/stream), followed redirects to expiring storage URLs and returned `206 audio/mpeg` with wildcard CORS; their 150px artwork loaded. The first hit was marked `is_streamable: false` and its stream returned `404` despite an `access.stream` value of `true`. Resolve on playback, keep the stable endpoint, and respect access and license flags. The tests establish anonymous access for those endpoints and tracks, not an anonymous quota or entitlement for all content; check the [developer reference](https://docs.audius.co/) and [service terms](https://audius.co/legal/terms-of-use) before shipping. “All rights reserved” results are not openly licensed.

### Jamendo and MusicBrainz: useful, but not keyless full-catalog substitutes

- **Jamendo:** the official [tracks API](https://developer.jamendo.com/v3.0/tracks) supports search, image, stream URL, duration and licensing metadata, but requires an application `client_id`. Consider only if a registered client and the [API terms](https://developer.jamendo.com/api_terms_of_use) fit; don't build on inferred Jamendo storage URLs from index results.
- **MusicBrainz + Cover Art Archive:** [MusicBrainz API](https://musicbrainz.org/doc/MusicBrainz_API) allows public reads with an identifying User-Agent and a one-request-per-second client limit; [recording search](https://musicbrainz.org/ws/2/recording?query=recording%3A%22Blue%20in%20Green%22&limit=1&fmt=json) returned JSON without credentials. [Cover Art Archive](https://musicbrainz.org/doc/Cover_Art_Archive/API) associates images with release/release-group MBIDs. Use as optional enrichment with license-aware artwork handling and exact release matches, not as a streaming source or as proof of a recording match.

## Worker and playback acceptance criteria

1. Keep search and resolution separate. Search cached item or track metadata; expand Archive file lists only for an opened result or a bounded number of results. Cache normalized metadata, apply timeouts and respect rate limits/`Retry-After`. Don't cache temporary redirect targets or broadcast a request to all providers for every keystroke. Use the Worker’s [Fetch API](https://developers.cloudflare.com/workers/runtime-apis/fetch/) and [cache facilities](https://developers.cloudflare.com/workers/cache/) for metadata, not as a general audio proxy.
2. Use source-qualified IDs (e.g. Archive item ID plus filename, not a YouTube video ID). Keep attribution, canonical page, license and separate artwork/playback URLs. Route provider IDs to their own resolver instead of running them through M14U's existing YouTube paths. Send the direct compatible media URL to the web or Android player.
3. Verify in a deployed Worker and on both players: one result with artwork, one without, startup, seek into the track, end-to-end playback, unavailable/gated results, and redirect and expiry handling. Missing CORS is not necessarily a blocker for a plain cross-origin `<audio>` playback URL, but can block CORS-enabled media or a browser `fetch`; test the actual code path. A `206` proves only that the sampled byte range was served. Live probes used shell HTTP clients, not a deployed Worker, browser, or Android device.
