# M14U on Android

Capacitor loads the live web UI directly from Cloudflare Pages. [`capacitor.config.ts`](../capacitor.config.ts) sets `server.url` to `https://m14u.pages.dev` (`cleartext: false`, `webDir: 'dist'` kept for Capacitor sync). Publishing web changes to `https://m14u.pages.dev` updates the UI on the next app load without rebuilding the APK.

Android does not use the website's catalog switch or welcome dialog. Because Capacitor injects the native bridge into the configured `server.url` origin, `isNative()` remains true and the app sends `catalog=youtube` for search and suggestions to the configured Cloudflare catalog Worker by default; stream extraction and playback use the JS-first + native pipeline below. For resiliency during YouTube failures or outages, [`jiosaavn.ts`](../src/services/jiosaavn.ts) permits explicit `{ allowNative: true }` calls from the guarded Android fallback ([`saavnFallback.ts`](../src/services/saavnFallback.ts) and outage-mode [`search.ts`](../src/lib/stores/search.ts)), and [`PlaybackService.kt`](../android/app/src/main/java/dev/m14u/app/PlaybackService.kt) resolves unprimed `jiosaavn:` tracks against `BuildConfig.JIOSAAVN_AUDIO_ORIGIN` (defaulting to `https://m14u-jiosaavn.onrender.com`).

## Offline fallback and origin isolation

[`MainActivity.java`](../android/app/src/main/java/dev/m14u/app/MainActivity.java) installs `OfflineBridgeWebViewClient` (backed by `OfflineFallbackPolicy`) over Capacitor’s `BridgeWebViewClient`:

- **Main-frame fallback:** When a main-frame navigation on the configured server origin hits a network error or HTTP `5xx`, the WebView loads the packaged [`public/offline.html`](../public/offline.html) (`file:///android_asset/public/offline.html`). Subresource errors do not trigger the fallback, and host/port/userinfo mismatches on the configured host are blocked.
- **No bridge on offline shell:** The offline page has no Capacitor bridge access (`hasCapacitor` is false) and active background playback in `PlaybackService` continues undisturbed.
- **Loop-safe retry:** Clicking **Retry** navigates only to the sanitized configured server origin (`window.location.replace`), preserves `?status=failed` if still unreachable, and clears WebView history once the remote origin finishes loading.

## Foreground JS extraction and native bridge

`MainActivity` registers three Kotlin plugins before bridge creation. Their TypeScript interfaces live in [`src/plugins/`](../src/plugins/).

- **JS-first foreground extraction:** On native Android, [`getStreamData.ts`](../src/lib/modules/getStreamData.ts) defaults to `VITE_YOUTUBE_JS_RESOLVER !== 'false'` and lazy-loads [`resolver/core.ts`](../src/lib/modules/resolver/core.ts) (`youtubei.js/web` with `VISIONOS` primary + QuickJS WASM `Player` fallback) paired with [`capacitorTransport.ts`](../src/lib/modules/resolver/capacitorTransport.ts) (explicit `CapacitorHttp.request` adapter with global `fetch`/`XHR` patching left disabled), racing the optional v1 [`liveResolver.ts`](../src/lib/modules/liveResolver.ts). On failure or deadline expiry, it falls back to `StreamExtractor` (`NewPipe`) and then Invidious. For `jiosaavn:` IDs on Android, `getStreamData.ts` unlocks `jioSaavnAudioUrl(id, { allowNative: true })` only when `useSaavnFallbackStore.getState().enabled` is true. [`lookahead.ts`](../src/lib/modules/resolver/lookahead.ts) pre-resolves up to two upcoming queue rows (using `resolveRowTrackId` so F1-remapped rows resolve their `jiosaavn:` match, and priming `jiosaavn:` rows on older APKs where `saavnUnprimed` is `false`) and pushes them natively via `setResolvedSources`.
- **Guarded JioSaavn fallback (F1 / F3):** [`saavnFallback.ts`](../src/services/saavnFallback.ts) (`useSaavnFallbackStore`) coordinates Android YouTube resiliency without altering `favorites` or library track IDs:
  - **F1 per-track fallback:** On Android `getStreamData` failure or a native open error before playback starts (`position === 0` on an unstarted YouTube row), `playerStore` records the failure and invokes `resolveTrackFallback` at most once per `queueId`. `findConfidentSaavnMatch` searches `searchJioSaavn(..., { allowNative: true })` and requires a strict title match (stripping benign YouTube tags and `Artist - Title` prefixes), symmetric qualifier sets (`live`, `remix`, `cover`, `instrumental`, `sped-up`/`nightcore`, `reverb`/`slowed`, `karaoke`, `acoustic`, `lofi`, `mashup`, `8d`), credible non-generic artist overlap, and duration within `15s`. On match, `playerStore` reloads `NativePlayback.loadQueue` with a fresh `generation` and `resolverKey: { provider: 'jiosaavn', trackId }`.
  - **F3 session circuit breaker & recovery:** `recordYouTubeFailure` opens `'jiosaavn-fallback'` mode after 3 distinct YouTube `trackId`s fail within 5 minutes (ignoring aborts, offline errors, and duplicate retries). While open and `enabled`, [`search.ts`](../src/lib/stores/search.ts) routes Android search and suggestions to `searchJioSaavn(..., { allowNative: true })` and triggers lazy `maybeProbeRecovery()`. Recovery probes are single-flight, skip offline or `document.hidden` states, back off `3m -> 6m -> 10m`, probe `resolveYouTubeStreams` + `.googlevideo.com` `Range: bytes=0-0` within `6500ms`, and restore `'youtube'` mode on success.
  - **UI & console controls:** [`AndroidFallbackNotice.tsx`](../src/components/player/AndroidFallbackNotice.tsx) renders the F1 match toast, F3 outage banner (`Retry YouTube`, `YouTube only` opt-out persisted in `m14u-android-saavn-fallback`), and restored toast; `m14u.fallback.*` (`status`, `retryYouTube`, `setEnabled`, `reset`) controls and inspects fallback state.
- **`NativePlayback` v2 ([`NativePlaybackPlugin.kt`](../android/app/src/main/java/dev/m14u/app/NativePlaybackPlugin.kt)):** Controls [`PlaybackService.kt`](../android/app/src/main/java/dev/m14u/app/PlaybackService.kt) and streams snapshots to React. `getCapabilities()` reports `abiVersion` (`2`), `sourceRefresh`, `localMedia`, `headlessResolver`, `sandboxSupported`, `saavnUnprimed` (`PlaybackService.isSaavnUnprimedSupported()`), and `resolverAbi` (`androidx-js-1`). `loadQueue` and `updateQueue` accept `generation`, typed `resolverKey`, and optional pre-resolved `source` (`url`, `mimeType`, allowlisted `headers`, `expiresAtMs`). `parseQueue` validates `jiosaavn` `resolverKey.trackId` (`[A-Za-z0-9_-]{1,64}`) and permits `resolverKey.provider == "jiosaavn"` without a pre-resolved `source`. `setResolvedSources({ generation, entries })` updates [`PlaybackSourceRegistry.kt`](../android/app/src/main/java/dev/m14u/app/PlaybackSourceRegistry.kt) without replacing `ExoPlayer` `MediaItem`s or disturbing the active buffer. Unresolved v2 rows use `m14u-resolve://track/<queueId>`, while legacy `m14u-track://youtube/<id>` remains supported.
- **`PlaybackService` headless v2, unprimed `jiosaavn:`, and transitional fallback:** On Media3’s loader thread (`PlaybackResolvingDataSource`), playback first opens any valid pre-resolved `source` from `PlaybackSourceRegistry` (clearing `DefaultHttpDataSource` headers per open/close and allowing at most one bounded retry on open failure). If missing or expired and `resolverKey.provider == "jiosaavn"`, `resolveJioSaavnAndOpen` validates `BuildConfig.JIOSAAVN_AUDIO_ORIGIN` (`parseSaavnAudioOrigin`: HTTPS on port 443, public host, path `/`, no query/fragment/userinfo; configurable via Gradle property or `JIOSAAVN_AUDIO_ORIGIN` env var, defaulting to `https://m14u-jiosaavn.onrender.com`), opens `${origin}/api/audio/<id>` directly, caches it in `PlaybackSourceRegistry` (`DEFAULT_TTL_MS`), and enforces the 1-retry budget without falling through to YouTube resolvers. Otherwise, it resolves via [`ResolverEngine.kt`](../android/app/src/main/java/dev/m14u/app/ResolverEngine.kt) (`AndroidX JavaScriptSandbox` on API 26+) and [`ResolverBundleRepository.kt`](../android/app/src/main/java/dev/m14u/app/ResolverBundleRepository.kt) using APK-pinned SPKI keys (`BuildConfig.RESOLVER_V2_PUBLIC_KEYS` / `RESOLVER_V2_MANIFEST_URL`). If headless v2 is unconfigured, unsupported, or fails, `PlaybackService` falls back transitionally to `StreamExtractorPlugin` (`NewPipe`) and legacy `proxy`.
- **`StreamExtractor` ([`StreamExtractorPlugin.kt`](../android/app/src/main/java/dev/m14u/app/StreamExtractorPlugin.kt)):** Provides the transitional NewPipeExtractor fallback. [`DownloaderImpl.kt`](../android/app/src/main/java/dev/m14u/app/DownloaderImpl.kt) is the extractor’s HTTP implementation, not an offline music-download feature. See [playback architecture](ARCHITECTURE.md#from-track-selection-to-playback) for fallback order.
- **`AppUpdater` ([`AppUpdater.kt`](../android/app/src/main/java/dev/m14u/app/AppUpdater.kt)):** Checks the latest GitHub release and handles APK download/install handoff. This is separate from both the v1 and v2 [signed live resolvers](LIVE-RESOLVER-SETUP.md), which only update stream-resolution logic. Changes to Kotlin, bundled dependencies, or packaged native assets require a new APK.

## Build and verify

Install the prerequisites in [setup](SETUP.md), then run `pnpm android:build`. The command builds the web app, syncs Capacitor, and runs Gradle’s `assembleDebug`. The APK is at `android/app/build/outputs/apk/debug/app-debug.apk`. Run `(cd android && ./gradlew :app:test)` for JVM unit tests (registry, repository trust, JioSaavn origin validation, offline policy, updater) and `pnpm test:resolver:smoke` for deterministic resolver smoke checks. `android/app/build.gradle` accepts `JIOSAAVN_AUDIO_ORIGIN` via Gradle property or environment variable (defaults to `https://m14u-jiosaavn.onrender.com`).

On a device, check search from the WebView, `NativePlayback.getCapabilities()`, audible playback and seeking, queue edits preserving active playback, background/screen-off auto-advance and lock-screen controls, offline cold-start fallback/reconnect, F1/F3 fallback behavior via `m14u.fallback.*`, and resume sync. Search failures point first to the built-in API URL or API reachability. If search succeeds but audio fails, distinguish stream resolution, media URL loading, and native service errors. A browser smoke test does not exercise the Android bridge.

### Local debug lane

Run Vite on the host loopback, then build and install the debug APK from another terminal (replace the serial with yours):

```sh
pnpm dev --host 127.0.0.1 --port 5173 --strictPort
ANDROID_SERIAL=ZA222R79W4 bash scripts/android-update.sh --local 5173
```

The script sets `CAPACITOR_DEBUG_URL=http://127.0.0.1:<port>`, builds and installs the debug APK, maps `adb reverse tcp:<port> tcp:<port>`, and launches `.MainActivity`. Without `--local`, it restores the production `https://m14u.pages.dev` origin. Inspect the WebView at `chrome://inspect/#devices`: `m14u.diagnostics()` should report `origin: "http://127.0.0.1:5173"`, `isNative: true`, and `platform: "android"`. Vite edits take effect without rebuilding the APK.

When finished, stop Vite, remove the reverse mapping with `adb -s ZA222R79W4 reverse --remove tcp:5173`, and run `env -u CAPACITOR_DEBUG_URL pnpm exec cap sync android` to restore the generated production config. Rerun the update script without `--local` to install the Pages-backed debug APK. Only the debug manifest permits loopback HTTP; [`capacitor.config.ts`](../capacitor.config.ts) refuses `CAPACITOR_DEBUG_URL` when `RELEASE_BUILD=true` (as in release CI) or `CAPACITOR_RELEASE=1` (enforced in CI sync). Always sync for production before assembling a release locally.

## GitHub releases

Increase `versionCode` and update `versionName` in `android/app/build.gradle`. Push the commit and a matching stable tag (`v` followed by `versionName`). [GitHub Actions](../.github/workflows/build-apk.yml) runs `pnpm test:resolver:smoke` during its web check job and verifies and publishes `m14u.apk` on version tag pushes, not ordinary branch pushes. A manual run without `verify_release` still uploads a debug APK. Separately, [`youtubei-sync.yml`](../.github/workflows/youtubei-sync.yml) runs daily `youtubei.js` sync PRs (`sync-and-test`, plus advisory `--live` probing) and `main` v2 resolver bundle signing (`sign-v2-bundle`); see [live resolver setup](LIVE-RESOLVER-SETUP.md).

To check release signing without publishing, run the workflow manually on `main` with `verify_release` enabled. Download the `m14u-release` artifact from the run.

Keep a private backup of the release PKCS#12 keystore (alias `m14u`) and password. The signing step reads `APK_KEYSTORE_BASE64` and `APK_KEYSTORE_PASSWORD` from GitHub Actions secrets. Android requires the same signing key for subsequent in-place updates. A debug installation signed with a different key must be removed before installing the release, which deletes its local data.
