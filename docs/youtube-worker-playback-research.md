# YouTube playback on Cloudflare Workers

## Findings

- **An audio format is not necessarily a playable URL.** In [YouTube.js v18.3.0's parser](https://github.com/LuanRT/YouTube.js/blob/v18.3.0/src/parser/parser.ts#L405-L418), adaptive formats, DASH/HLS manifests, and `server_abr_streaming_url` are separate fields. [`Format.url` is optional](https://github.com/LuanRT/YouTube.js/blob/v18.3.0/src/parser/classes/misc/Format.ts#L130-L150), and [`Format.decipher()`](https://github.com/LuanRT/YouTube.js/blob/v18.3.0/src/parser/classes/misc/Format.ts#L248-L256) requires a direct URL or cipher input to resolve a direct stream. If a playable response supplies audio descriptors and a SABR endpoint but no direct or ciphered audio URLs, changing itags or calling `getStreamingData()` will not manufacture a URL: [that helper selects and deciphers a format](https://github.com/LuanRT/YouTube.js/blob/v18.3.0/src/Innertube.ts#L449-L463).
- **SABR is a separate playback protocol, not a substitute URL for the native audio player.** The YouTube.js project's companion [GoogleVideo adapter](https://github.com/LuanRT/googlevideo/blob/main/src/core/SabrStreamingAdapter.ts) sends binary POST requests and handles UMP responses and session state. YouTube.js has [SABR manifest-generation support](https://github.com/LuanRT/YouTube.js/pull/974), but that is not a drop-in native URL fix. The companion package's [JSR compatibility listing](https://jsr.io/@luanrt/googlevideo/doc/sabr-streaming-adapter) does not confirm Workers support. This is community tooling, not a YouTube-supported playback API.
- **`LOGIN_REQUIRED` is an upstream playability result, distinct from missing URLs and decipher failures.** The [v18.3.0 download helper](https://github.com/LuanRT/YouTube.js/blob/v18.3.0/src/utils/FormatUtils.ts#L16-L36) checks it before choosing or deciphering a format. [Upstream issue #748](https://github.com/LuanRT/YouTube.js/issues/748) provides a report of behavior differing between a local machine and a remote server, not proof that Cloudflare IPs are blocked or that a Cloudflare configuration change fixes it. Do not infer the cause from the status alone; preserve the upstream reason separately from the HTTP status. No reliable, supported Cloudflare-side cure was identified.
- **The evaluator is a third, independent failure mode.** The [v18.3.0 web build](https://github.com/LuanRT/YouTube.js/blob/v18.3.0/src/platform/web.ts#L106-L113) uses a [stub evaluator](https://github.com/LuanRT/YouTube.js/blob/v18.3.0/src/platform/jsruntime/default.ts) unless one is supplied. [The standard Workers runtime disallows `eval()` and `new Function`](https://developers.cloudflare.com/workers/runtime-apis/web-standards/#javascript-standards). An evaluator can only help when a URL or cipher exists and actually needs processing; it does not resolve `LOGIN_REQUIRED` or turn a SABR endpoint into a direct URL.

## Supported options and next checks

1. **For YouTube playback, use the visible [YouTube IFrame Player API](https://developers.google.com/youtube/iframe_api_reference)** or offer **Open in YouTube** when embedding is unavailable. A WebView embedding must meet YouTube's [client-identification and Referer requirements](https://developers.google.com/youtube/terms/required-minimum-functionality#embedded-player). This is not a replacement for audio-only/background playback: [YouTube's API developer policies](https://developers.google.com/youtube/terms/developer-policies) prohibit separating audio and using a hidden background player. If native/background audio is mandatory, use media the app controls or is licensed to stream through a provider that supports that mode.
2. **Keep catalog success independent of playback availability.** On an authorized direct-media path, distinguish upstream rejection, SABR-only, missing media, decipher failure, and downstream media HTTP failure. Avoid blind retries, account-cookie sharing, or proxy/client rotation as production fixes. Compare the same known public, embeddable video and pinned library/client locally and in the deployed Worker. Capture HTTP status, playability status/reason, and counts of direct/ciphered/audio formats plus SABR/manifest presence; do not log full URLs, tokens, or cookies. Verify audible playback on Android, not only URL resolution (see [Live resolver setup](LIVE-RESOLVER-SETUP.md)).

This is source research, not a live reproduction. Confirm the deployed resolver's dependency version before attributing behavior to v18.3.0; the root [`package.json`](../package.json) in this checkout declares `^16.0.1`.
